ISR — resolved via a different route than originally planned:

  • On-demand ISR via cache tags — done, verified live. Route-level revalidate couldn't work here (this route tree reads headers() for tenant resolution, which forces fully dynamic rendering regardless). Instead, fetchPageData/fetchPageMeta are now wrapped in unstable_cache, tagged site:<domain>/page:<siteId>:<slug>. Verified with a request-count test: 3 requests to the same page → 1 real DB query.
  • Found and fixed a real pre-existing bug along the way: afterChangePublishRevalidate.ts's tag builder only accepted a string site id, but Postgres-backed Payload ids are numbers — so the page-level revalidate tag silently never fired for any page, ever, until this pass. Verified the fix live: publish → cache invalidates → next request shows fresh content.

Still open:

  • hreflang unused. Moot until an IT sibling exists, but packages/seo's hreflang builder isn't wired in even structurally.
